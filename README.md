## v3.18 ON/OFF 둘 다 근거 포함
- 이전에는 OFF(해제) 메시지에 근거 섹션이 통째로 빠졌습니다 — OFF는 정의상 "활성 배경색이 없는 상태"라서, ON 근거를 만드는 로직(`_sig_evidence_text`)이 빈 문자열을 반환했기 때문입니다.
- 이제 ON과 OFF 각각 다른 형태의 "E-RANG 실제 판정 근거"를 보여줍니다:
  - **ON**: 지금 감지된 배경색 + 매치된 CSS 규칙 + 라벨 텍스트
  - **OFF**: 직전에 감지됐던 배경색이 무엇이었는지 + 기본색으로 복귀했다는 사실 + **몇 초/몇 분간 켜져 있다가 꺼졌는지(활성 유지 시간)**
- Binance 지표 참고 섹션도 ON/OFF 각각 "진입 시점" / "해제 시점" 라벨을 붙여서 두 메시지 모두에 포함됩니다.

## v3.32 실현손익이 카운트 안 되던 버그 수정 (tradeSide 값 불일치)
- **버그**: 실제 Bitget 응답의 `tradeSide` 값은 평범한 `"open"`/`"close"`가 아니라 **`"open_long"`/`"open_short"`/`"close_long"`/`"close_short"`처럼 방향까지 붙어서** 옵니다. 코드가 정확히 `"close"`와만 일치하는지 검사해서, 실제 청산 체결(`close_short` 등)의 `execPnl`이 전부 "실현손익 아님(None)"으로 조용히 빠지고 있었습니다. 그 결과 "지금까지 수익PNL", "PNL(통합)", "승률"이 실제 체결이 있어도 계속 0/빈 값으로 나오는 문제가 있었습니다.
- **수정**: `tradeSide`가 정확히 `"close"`인지가 아니라 `"close"`로 **시작하는지**로 검사하도록 바꿨습니다 (`close`, `close_long`, `close_short` 전부 인식). `compute_open_positions()`의 open/close 판정도 동일하게 고쳤습니다.
- 회귀 테스트로 실제 스크린샷의 체결(`tradeSide: close_short, execPnl: 0.0149`)을 그대로 재현해서 이제 정확히 카운트되는 것을 확인했습니다.

## v3.28 진짜 실시간 포지션 API로 교체 (추정 → 실제)
- v3.27의 "추정" 방식(체결내역에서 open/close 계산)을 **진짜 실시간 포지션 조회 API**(`GET /api/v3/position/current-position?category=USDT-FUTURES`)로 교체했습니다. 사용자가 실제 Bitget 문서를 확인해줘서 가능했습니다.
- 이제 포지션마다 다음 필드를 그대로 보여줍니다: 종목(symbol) · 방향(posSide: long/short) · 진입 평균가(avgPrice) · 현재 마크가(markPrice) · 레버리지(leverage) · 수량(holdSize) · 포지션 가치(positionValue) · 미실현손익(unrealisedPnl) · 예상 청산가(liqPrice) · 마진(positionBalance) · 마진모드(marginMode).
- "현재 포지션" 탭/카드에서 "(추정)" 표시와 관련 안내 문구를 모두 제거했습니다 — 이제 진짜 데이터입니다.
- `compute_open_positions()`(체결 기반 추정 로직)은 코드에는 남겨뒀지만 더 이상 사용하지 않습니다 (혹시 필요하면 나중에 참고용으로 쓸 수 있습니다).

## v3.27 "현재 포지션 (추정)" 탭 추가
- Bitget V3 통합계좌 API에는 실시간 포지션 조회 엔드포인트가 없어서, **체결 내역(fills)의 open/close를 직접 계산해서 현재 남아있는 포지션을 추정**하는 기능을 추가했습니다 (`bitget_client.compute_open_positions`).
  - 심볼별로 open 체결은 더하고 close 체결은 차감(비례 배분)해서 남은 수량 + 평단가를 계산합니다. 여러 심볼/롱·숏 동시 보유도 각각 독립적으로 추적합니다.
  - 미실현손익은 표시하지 않습니다 — 종목별 실시간 시세가 없어서 억지로 계산하면 틀린 값을 보여줄 위험이 있기 때문입니다. 전체 계좌 미실현 PNL은 계좌자산 API 값을 그대로 씁니다.
  - **한계**: 조회한 체결 내역 범위보다 더 예전에 진입한 포지션이 있으면, 그 이전 open 체결이 안 잡혀서 실제보다 수량이 적게 나올 수 있습니다. 화면에도 이 안내 문구가 항상 보입니다.
- "내 Bitget 계좌" 카드에 **"현재 포지션 (추정)"** 탭을 첫 번째(기본 선택) 탭으로 추가했습니다. 상단 "현재 포지션" 미니 카드도 이 추정 포지션 목록(심볼·LONG/SHORT·수량)을 보여주도록 바꿨습니다.

## v3.26 Bitget Unified Trading Account V3 API로 전면 교체
- v2 mix API(`/api/v2/mix/...`)와 그 추정 변형(`/api/v2/uta/...`)이 모두 실패해서, 사용자가 직접 확인해준 **실제 문서 기반 V3 통합계좌 API**로 완전히 다시 작성했습니다.
- 엔드포인트: `GET /api/v3/account/assets` (계좌 자산), `GET /api/v3/trade/fills?category=USDT-FUTURES` (체결 내역), `GET /api/v3/trade/history-orders?category=USDT-FUTURES` (주문 내역).
- **"오픈 포지션" 개념이 사라졌습니다** — V3 API에 실시간 포지션 목록 엔드포인트가 없어서(문서에 없음), 카드 이름을 "내 Bitget 계좌"로 바꾸고 지표를 재구성했습니다:
  - 요약: 총자산(accountEquity) / USDT 잔고(usdtEquity) / 미실현 PNL(usdtUnrealisedPnl) / 유효자산(effEquity) / 승률 / PNL(통합)
  - 탭: 체결 내역(fills) / 주문 내역(history-orders) — "보유 포지션" 탭은 제거
  - 승률/실현손익은 체결 내역 중 `tradeSide=close`인 것들의 `execPnl`을 집계해서 계산합니다.
  - 상단 미니 카드도 "최근 체결" 기준으로 바뀌었습니다.
- 환경변수: `BITGET_CATEGORY`(기본 `USDT-FUTURES`), `BITGET_SYMBOL`(선택, 특정 심볼만 보고 싶을 때). `BITGET_ACCOUNT_MODULE`은 더 이상 쓰지 않습니다(V3는 mix/uta 구분이 없는 별도 API 트리라서).

## v3.25 통합계좌(UTA) 지원 + 에러 메시지 정확도 개선
- **[40085] Unified Account mode 오류 수정 시도**: 비트겟이 "통합계좌(Unified Trading Account)" 모드인 계정에서 클래식(Classic) 전용 API(`/api/v2/mix/...`)를 호출하면 이 오류가 납니다. 엔드포인트 경로의 계좌 구간(`mix`)을 환경변수 `BITGET_ACCOUNT_MODULE`로 뺐고, 기본값을 `uta`로 바꿨습니다 (클래식 계좌를 쓰는 다른 배포는 `BITGET_ACCOUNT_MODULE=mix`로 되돌리면 됩니다).
  - ⚠️ **주의**: 통합계좌(UTA) API의 정확한 경로/파라미터는 실시간 문서로 검증하지 못한 상태의 최선의 추정입니다 (`/api/v2/uta/...`). 틀렸다면 다른 형태의 오류(404 또는 다른 code/msg)가 나올 텐데, 그 메시지를 알려주시면 경로를 다시 맞출 수 있습니다 — 코드가 아니라 환경변수만 바꾸면 되므로 재배포 없이 바로 테스트 가능합니다.
- **에러 메시지 정확도 개선**: 이전에는 4xx/5xx HTTP 상태에서 `resp.raise_for_status()`가 먼저 터져서 비트겟이 실제로 응답 본문에 담아 보낸 `{code, msg}`(진짜 원인)를 볼 수 없었습니다. 이제 HTTP 상태와 무관하게 먼저 JSON 본문을 파싱해서 비트겟의 실제 에러코드/메시지를 그대로 보여줍니다 (예: `[40085] You are in Unified Account mode...`).

## v3.24 승률 / PNL(통합) / 총 USDT 잔고 추가
- "내 Bitget 포지션" 카드 요약 줄에 3개 지표가 추가됐습니다: **승률**(N승 M패), **PNL(통합)**, **총 USDT(잔고)**.

  - **승률**: 청산된 포지션 이력(`/api/v2/mix/position/history-position`)에서 실현손익 > 0인 거래 수 ÷ (실현손익 > 0 또는 < 0인 거래 수). 정확히 0(본전)인 거래는 승/패 어느 쪽에도 넣지 않고 분모에서도 제외합니다.

- ⚠️ **참고**: Bitget API의 정확한 응답 필드명은 실시간으로 문서를 확인할 방법이 없어 알려진 표준 규격 기준으로 만들었습니다. 실제 계좌에 연결했을 때 숫자가 이상하거나 `-`로만 나오면, `/api/bitget-live` 응답을 보여주시면 필드명을 실제 값에 맞게 바로 고쳐드릴 수 있습니다.

## v3.19 롱/숏 진입가 동시 표시 + 알림 누락 방지 강화
